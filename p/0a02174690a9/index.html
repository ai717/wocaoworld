Jellyfish开源短剧工作台：AI短剧从剧本拆解到资产一致性实战

为什么传统视频工具做不好长篇连续短剧
在生成式视频技术爆发的背景下，大部分创作者仍被困在单镜头抽卡与碎片化生成的泥潭中。市面上多数工具仅能解决单次生图或短视频生成，但在面对具备强叙事连贯性的短剧时，角色脸部漂移、服化道前后割裂、镜头提示词难以追溯等痛点极为严重。面向短剧与微短剧制作的开源端到端工作空间 Jellyfish（AI Short Drama Studio）的推出，正是为了将割裂的生成环节整合成工业级流水线，系统化解决AI短剧在剧本结构化拆解、多镜头一致性维系以及批量生成编排中的核心工程难题。
Jellyfish 的定位并非普通的单一多模态生成外挂，而是一个以生产资产为核心的工作台（Production Workspace）。它将剧本分镜、候选资产、对白、镜头提示词与生成任务全部资产化与可复用化，让整个创作链路从灵感输入到母带导出形成闭环可追溯的数据流。

Jellyfish核心工作流的三大支柱

系统围绕现代剧组的实际编排逻辑，构建了高内聚的三个阶段流程：

一、AI剧本理解与镜头级候选拆解

工作流的第一步是以章节（Chapter）为单元载入剧本文案。内置的语言模型引擎能够深入解析剧情脉络，自动执行以下自动化动作：
剧本拆镜头：按叙事节奏切分为独立 Shot，并提取关键对白与情绪氛围；实体候选捕捉：自动识别并标记角色（Characters）、场景（Scenes）、道具（Props）与服装（Costumes）；智能核验与调优：在分镜前自动运行剧本一致性检查、台词精简与人物小传分析，将粗糙文学稿转化为工程可落地的镜头清单。
二、资产确权与镜头准备度工作流
在真正启动昂贵的生图与生视频任务前，Jellyfish 引入了严谨的准备确认环节。创作者可以对提取出的候选资产进行采纳、忽略或关联已有资产库中的经典形象，强制推行命名排重以最大化复用已有模型资产。只有当关键帧参考图、对白、提示词均被人工或算法标定就绪后，镜头才会流转至 Shot Ready 状态，从而避免了无效算力浪费。

三、镜头编排与全局统一异步任务中心

进入生成工作区后，系统支持关键帧管理、参考图挂载与镜头级视频提示词实时预览。无论是文本优化、单张关键帧渲染还是视频批处理，所有长周期计算均接入统一的全局异步任务体系。创作者可以在控制台直观查看任务进度、耗时与执行结果，并支持一键取消或上下文快速跳转回关联的镜头节点。

Docker Compose极速私有化部署实操

Jellyfish 提供了高度封装的容器化配置文件，底层依赖 MySQL、Redis 与 RustFS 存储，开发者只需几个步骤即可在本地或工作站拉起整套微服务：

第一步：配置运行环境变量

进入部署目录并根据示例模板生成生产环境配置：

cp deploy/compose/.env.example deploy/compose/.env

第二步：构建并启动容器集群

执行标准构建与编排命令：

docker compose –env-file deploy/compose/.env -f deploy/compose/docker-compose.yml up –build

服务启动后默认暴露以下端口与入口：

前端工作台 WebUI：访问 http://localhost:7788；后端核心服务与 OpenAPI 文档：访问 http://localhost:8000/docs；RustFS 对象存储服务：访问 http://localhost:9000；数据库与缓存：MySQL 监听 3306 端口，Redis 监听 6379 端口。

第三步：前端契约同步与本地二次开发

如需进行前后端深度定制，后端支持使用现代化管理工具 uv 进行依赖同步（uv sync && uv run uvicorn app.main:app –reload）；前端基于 pnpm 构建，修改后端数据模型后，仅需在前端目录执行 pnpm run openapi:update，即可通过 front/openapi.json 自动重新生成类型与客户端请求接口。

工业化落地的三大避坑准则

在运用此类 AI 工作台进行大规模短剧产出时，需要建立以下工程化心智：
先建资产库，后开分镜槽：切勿直接在空白镜头中无休止地临时生成新角色。先在资产中心将核心主角、反派与主场景的参考立绘定稿锁定，再通过镜头实体绑定进行引用，才能从根本上扼杀跳戏失真。区分「已就绪」与「正在生成」状态：严格遵循状态机规则。在批量下发生成任务前，务必对全章节镜头的提示词参数与画幅预设进行单镜头预检（Pre-check），防止大批量失败造成 API 账单激增。善用异步中心做故障隔离：长时间运行的文生视频请求受制于网络与上游 API 吞吐，如果偶发超时或丢包，直接在全局任务看板中执行单个重试，无需重置整个章节序列。
