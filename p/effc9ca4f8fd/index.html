GitHub高星AI短剧项目盘点：从一句话到成片怎么选工具

这些仓库在解决同一件事

GitHub 上几款高星AI短剧项目，把剧本、分镜、角色、配音和成片串成一条流水线。一句话、一本小说或一段主题丢进去，就能往外吐竖屏片子。工具能缩短制作链路，并不能替你过平台审核，也不能替你把播放量变成稳定收入。

六个仓库定位并不重复。有的赌“一句话出全集”，有的专啃小说改编，有的把角色一致性当成主战场，有的更像短视频引擎而不是剧组工作台。选之前先看输入是什么：一句话、现成剧本，还是几十万字小说。

六个项目各自擅长什么

火宝短剧：一句话走完全流程

chatfire-AI/huobao-drama 自称一站式短剧平台：大模型拆剧本、抽角色和场景，再走绘图与文生视频、图生视频，最后合成。星标约1.4万，TypeScript 全栈，Web 里填 API Key 即可换模型。适合先验证“这个题材能不能拍成剧”，不适合把第一版成片直接当可上架成品。

Toonflow：小说和剧本转漫剧

HBAI-Ltd/Toonflow-app 是开源桌面端，Windows、macOS、Linux 都有安装包，星标约1.5万。它把小说、剧本转成动画短剧，编剧、分镜、角色和视频生成打在同一个客户端里。已有文字资产、又想走漫画或动画风格时，这条路径比从零写分镜省事。

Pixelle-Video：主题进，短视频出

AIDC-AI/Pixelle-Video 星标最高，约2.7万。输入一个主题，自动写文案、配图、配乐、出片，也支持漫画风和数字人口播。它更像全自动短视频引擎，Windows 有一键整合包，零基础能跑起来。做知识口播、产品讲解会更顺；要多集人物关系稳定的短剧，还得另接一致性方案。

Jellyfish：把剧组流程收进工作台

Forget-C/Jellyfish 覆盖剧本输入、智能分镜、角色场景道具一致性、视频生成、后期和导出。卖点是全局种子、统一风格和资产复用，专门对付人物脸漂、服装乱换。准备认真连载、而不是只出一条测试片时，这类工作台比“一键出片”更接近真实生产。

waoowaoo：按工业流程拆小说

saturndec/waoowaoo（现多在 waooAI 组织下维护）定位工业级 AI 影视生产：扔进小说后自动拆分镜、定角色、出视频、配配音。星标约1.4万。流程完整，部署和模型成本也更高，适合已经接受“生成只是初剪”的团队。

ViMax：长篇改编有单独模块

HKUDS/ViMax 是港大相关实验室开源的智能体视频框架，星标约1.2万。内置 Idea2Video、Script2Video，以及针对长篇小说的 Novel2Video：先压缩叙事、追踪角色、规划场景，再往分集画面走。手里是网文、出版小说，而不是一句梗，优先看这一支。

怎么配对输入

项目 更合适的输入 风格偏向 部署形态
火宝短剧 一句话、短大纲 真人/生成视频短剧 Web 自托管
Toonflow 小说、剧本 动画、漫剧 桌面客户端
Pixelle-Video 主题、口播文案 短视频、漫画、数字人 整合包 / 本地 Web
Jellyfish 分集剧本 竖屏微短剧连载 生产工作台
waoowaoo 长文本、小说 影视向全流程 平台级部署
ViMax 创意 / 剧本 / 长篇小说 分集改编 Agent + Web UI

能上平台，不等于能稳定变现

仓库 README 爱写“全自动”“零基础”。实际账单分三截。第一截是模型费用：文本、绘图、视频、语音往往要自备 Key，视频按秒计费，一条竖屏短剧就能把测试额度打穿。第二截是一致性：同一角色换场、换服装、换光线，仍是生成视频的主故障。第三截是平台规则：搬运同质化 AI 剧、未授权小说改编、伪造的“真实事件”，都可能限流或下架。

更稳的用法是把这些项目当制片助理。Pixelle-Video 和火宝短剧用来打样，看节奏和题材有没有钩子。Toonflow、ViMax 接已有文字。Jellyfish、waoowaoo 在确定要连载后再上，把角色和场景做成可复用资产。成片仍要人工过一遍对白、字幕、封面和前三秒钩子，平台推荐不会因为仓库星标高就让步。

版权也要单独算。小说转短剧先确认改编权；角色脸和声音不要直接套用在世演员或现成明星素材。工具降低的是制作门槛，不是内容责任。

按目标选一条链路即可

只想今晚出一条竖屏测试，用 Pixelle-Video 或火宝短剧。手里有小说要改漫剧，打开 Toonflow；要分集压缩长篇，走 ViMax 的 Novel2Video。准备按周更新、还要脸不漂，把时间花在 Jellyfish 或 waoowaoo 的资产管理上。

六个项目证明短剧生产正在被拆成可编排的步骤。真正拉开差距的，仍是题材是否站得住、前三秒是否留人，以及你愿不愿意在自动成片之后再剪一刀。
