校门口煎饼摊：不会代码也能挂进笔记

小红书笔记里能挂小游戏，这件事对不会写代码的人意味着什么？作者用 Claude Code 做了「校门口煎饼摊」，全文给出分步提示词，玩法是摆摊经营的轻量小游戏。原帖在 X，长文在 X 文章。本站环境打开 X 返回 403，未能直读原文，以下事实据任务单摘要整理，提示词细节以原文为准。

做法的分工很清楚：人定玩法和文案，Claude Code 按分步提示词生成网页文件包，成品上传到小红书小工具入口。煎饼摊这类题材适合练手：操作只有点按和选择，数值就是价格、配料和顾客满意度，不需要复杂引擎，一个网页文件包就能跑。

三条硬规则：文件包不能联网要审核

作者写清了小红书小工具的三条硬规则：上传的是网页文件包、不能联网、要审核。不能联网意味着游戏逻辑和素材都要打进包里，外部接口、在线排行榜、云端存档这类依赖联网的功能做不了，设计时先按离线单机规划。要审核意味着提交后等平台过审，文案和玩法别碰敏感题材，预留改稿轮次。

上传入口是创作者服务中心到 Builder Hub 再到小工具。作者写文时还没上传，所以不谈流量，这一点要分清：第 79 条「Builder 社群转述」的流量扶持说法仍为社群转述、未官方证实，不得与本条三条硬规则混为一谈。本文只写三条硬规则与制作分工，不承诺流量。

分步提示词怎么用：先玩法后界面

分步提示词的顺序决定成败。先让 Claude Code 出玩法骨架：摊位界面、顾客排队、点按出餐、结算金币，跑通一局完整流程。再补界面细节：配料选择、价格调整、顾客评价。最后打包成网页文件包，按不能联网的约束检查所有引用都是包内文件。原帖给出了分步提示词全文，本站未直读，不在此复述具体措辞，照原文复制时把题材换成你的。

离线约束下的设计取舍：存档用本地存储，素材全部内嵌，字体用系统字体，图片压缩到包体可接受范围。审核约束下的取舍：题材选日常经营、益智、打卡这类安全区，文案避开夸大收益和敏感词，提交前自己完整玩一遍找死链和卡死点。

适合练手的题材：单机点按类优先

适合这个入口的题材是单机点按类：经营摊位、消除、答题、打卡、抽签。共同点是逻辑闭合、不需要联网、不需要账号系统。煎饼摊的经营循环就是模板：进货、定价、服务、结算、升级，一局几分钟，适合笔记里随手点开玩。
