给Muse装X情报四件套：帖子丢过去就出情报

 

把帖子丢给 Muse：四件套分工先讲清

想让 Muse 变成 X 情报研究工具，不用装大而全的平台，四个小工具拼起来就够。读帖的三件套是 FxTwitter、vxTwitter 与官方 oEmbed，搜索那条腿是 Grok Build CLI 的 x_search。分工很清楚：FxTwitter 负责把帖子链接转成可读正文、图片、视频与点赞数，vxTwitter 是同类备用，官方 oEmbed 只回正文与作者，Grok Build 按关键词与语义搜 X、抓完整讨论串。

读帖三件套怎么配：FxTwitter 当主力

主力是 FxTwitter，也就是开源项目 FixTweet：把 x.com 的链接换成 fxtwitter.com 就能拿到帖子的 JSON，含正文、图片、视频与点赞数，Muse 读 JSON 比读网页省事得多。vxTwitter 是同类备用，逻辑一样，区别是它取不到浏览量，主力挂了再切过去。官方 oEmbed 是第三条路，地址在 publish.x.com/oembed，只回正文与作者，信息最少但最稳定，当前面两个都失效时兜底。三件套都是免费的，但前面两个是第三方非官方服务，随时可能失效，别把工作流全押在它们身上。

搜索那条腿要花钱：Grok Build 不是免费的

读帖免费，搜索不免费。Grok Build CLI 的 x_search 能按关键词与语义搜 X、抓完整讨论串，但这条腿要 Grok 或 X 付费套餐，或者自己的 API key，不是全免费。配的时候把这点写进预算：日常读帖零成本，批量搜帖、定时巡查就要算 API 账。另有一篇一天前的日文实操文描述的正是同一套 Muse 配置，可佐证方法可复现，这里的 Muse 确为 Meta Muse。

老法师避坑提醒：FxTwitter 与 vxTwitter 都是第三方服务，X 一改接口就可能失效，关键任务别只留一条读帖通道；搜索依赖付费套餐或 API key，批量任务先看清计费，别让一次巡查烧掉整月预算。

从读帖到情报：Muse 自配工具的完整链路

链路跑起来是这样：把帖子链接丢给 Muse，它先调 FxTwitter 取正文、图片、视频与互动数，再用 Grok Build 的 x_search 按关键词搜相关讨论、抓完整讨论串，最后把多条帖子拼成一份情报摘要。oEmbed 在旁边当备胎，FxTwitter 失效时顶上。整套配置不用写代码，Muse 自己配工具、自己调接口，配一次就能反复用。情报研究的门槛不在工具，在问题问得够不够具体。
