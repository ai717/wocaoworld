Decider 决策模型开源了：专判是非选择题的 AI

 

为什么把决策模型当“裁判”而不是“写手”

大多数 LLM 还在比拼生成长文，但 Perplexity 把目标锁定在“判断”上：给一段上下文，直接输出是非、打分或选项。这种 pplx-decider-v1.3 不会帮你写代码，只会帮你把成百上千个 Agent 会话里的隐患挑出来。

模型规格与开源协议

  • 基座 Qwen3.8-27B 微调，约 27B 参数，BF16 权重约 49 GiB
  • 蒸馏版 pplx-decider-flash-v1.3 基于 Qwen3.5-4B，约 4B 参数，BF16 约 8.5 GiB
  • 协议 Apache-2.0，权重托管在 Hugging Face

OpenRouter 上的零成本调用细节

截至 2026-11-13 在 OpenRouter 页面显示输入输出均为 $0/M，页面未标注截止日，免费随时可能结束，以页面实时价格为准。模型 ID 分别为 perplexity/pplx-decider-v1.3:free 与 perplexity/pplx-decider-flash-v1.3:free，上下文窗口 262,144 tokens。

专用 /api/alpha/decisions 端点

调用时不能走通用 Chat Completions，必须 POST 到 /api/alpha/decisions，请求体里带上 model 与 messages，返回结构里直接包含 decision、score 等字段，省去二次解析。

核心新能力 locate：按指令抽取原文位置

新增 locate 参数可让模型把判断依据的原文片段连同起止字符位置一并返回，单次最多 128 个 locate 问题。这在做合规审计、安全规则定位时比人工 grep 快一个数量级。

自报评测数字怎么读

厂商自报：63 个查询分类任务平均准确率 91.6%，100 万真实 API 请求与前沿模型裁判一致率 93.98%。这些数字均为 Perplexity 自报，未经独立第三方复现，拿来做选型参考可行，做 SLA 承诺则需自行跑测。

自托管门槛与真实成本

权重开源不等于“下载即用”。自托管需要 CUDA GPU、Python 3.12+ 环境，且 27B 版本显存占用约 49 GiB，4B 版本约 8.5 GiB。没有现成 GPU 集群的团队，直接用 OpenRouter 免费额度更划算；等免费窗口关闭再评估自建 ROI。

它和聊天模型根本不是一回事

Decider 决策模型和大家天天用的聊天模型走的是两条路：聊天模型负责生成文本，Decider 只负责下判断。它不写句子，只对你给的输入返回一个概率结果：这件事是还是不是、这 255 个选项里选哪个、这段内容打几分。一次请求里可以塞多个问题，批量判完一次返回，省掉了来回对话的开销。想让它干活，不能走通用的 Chat Completions 接口，得调 OpenRouter 专门的 /api/alpha/decisions 端点，请求体里带上模型名和问题，返回里直接就是 decision 和 score 字段，拿回来就能用，不用再写解析代码抠答案。

价格上也有个参照系：上一代 v1.2 在 OpenRouter 上是输入每百万 token 0.02 美元，Flash 版 0.01 美元，输出免费；v1.3 这次直接标到 0 美元，等于是把决策这件事的边际成本先打到零。对个人开发者来说，这意味着以前舍不得上的批量判断——比如给爬回来的几千条内容打标签、给 Agent 的每一步做合规检查、给客服对话做意图分类——现在可以先跑起来再算账。免费窗口能开多久没人打包票，OpenRouter 页面上也没写截止日，先用起来、把调用封装成独立模块，万一哪天收费了再换模型，改动最小。

别和另外两个同名决策接口搞混

最近决策模型这个赛道有点热闹，名字还撞车：Google 刚上了 Gemini Decisions API，OpenAI 也有一个 Decisions API，加上 Perplexity 的 Decider，三个完全是不同产品。Google 的是自家云上的决策接口服务，OpenAI 的是另一套，Perplexity 这次是把权重本身按 Apache-2.0 开源了，能下载、能自托管、也能走 OpenRouter。认准模型 ID perplexity/pplx-decider-v1.3:free 再动手，别在别的平台上搜个 Decision 就当成同一个东西。
