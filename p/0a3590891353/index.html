Agent 写 film.html、浏览器剪辑：这间 AI电影工作室真能出 4K

开门只要一条命令：Node 和终端是唯二的门票

动手前先把环境备齐，清单短得离谱：装好 Node.js（npx 能跑就行）、一个能打开的终端、能正常访问 GitHub。没有显卡要求，没有 Python 依赖地狱，因为渲染和预览都发生在浏览器里。项目在 GitHub 上约 3.5k star，挂的是 MIT 许可，商用、魔改、套壳都不用交钱，源码就在 openfilm/openfilm 仓库里躺着。

安装本身就是一句话：npx skills add openfilm/openfilm。这条命令把 OpenFilm 的整套技能定义装进你本地 Agent 的 skills 目录，装完之后 Claude Code、Codex 这类 coding agent 就认识了「拍电影」这项新技能。注意别装错仓库：GitHub 上还有个 WickyGinger/openfilm 的同名早期仓库，认准 openfilm 组织名下的那个才是正主。

让 Agent 写 film.html：frame(t) 是整件事的开关

OpenFilm 的核心设计反直觉：它不搞时间线工程文件那套，所有镜头收拢在一个叫 film.html 的单文件里。你要做的就是跟 Agent 说人话——「给我一段 10 秒的城市夜景转场，霓虹灯闪一下」——Agent 负责把描述翻译成代码，写进 film.html。

这个文件的灵魂是 frame(t) 函数：t 是时间，函数返回每一帧该长什么样。想加转场、改运镜、调配色，本质都是改这个函数。底层渲染走 three.js、WebGL、SVG、GSAP 这些现成的 Web 技术栈，所以 Agent 生成的代码不需要你懂图形学，改得动 JavaScript 就能二次加工。官方文档在 openfilm.dev/docs/cli，CLI 的每个子命令都有说明。

浏览器里的剪辑台：拖拽改字、时间线实时看

代码写完不用导出、不用进剪辑软件，直接在浏览器里打开 Studio 就能剪。官方原话是「Studio runs on your machine, in your browser」——预览和编辑全在本地跑，素材不上云。拖拽挪位置、滚轮缩放、双击改字、时间线 scrub，每一步都是实时反馈，改完立刻看到效果。

有个细节很对味：look 命令会做双序渲染来检测闪帧。做过逐帧动画的都知道，闪帧这种问题肉眼看预览不一定抓得住，工具替你跑两遍渲染比对，把有问题的帧揪出来，省得成片之后才发现。

openfilm render –4k：从预览到成片就一句话

剪辑满意了，渲染命令同样简单：openfilm render --4k。输出格式给得很实在：4K MP4、GIF、带透明通道的 webm（做贴纸和叠加层刚需）、字幕文件、stems 分轨，还能直接导出 Final Cut Pro、Premiere Pro、DaVinci Resolve 的时间线工程——这意味着你在 OpenFilm 里拼好的节奏，可以无缝丢进专业剪辑软件继续精修，而不是从零重来。

整条链路跑下来，Agent 负责写代码出初版，你在浏览器里当导演改细节，最后一条命令出成片。对独立创作者来说，最大的变化是试错成本：以前改一个转场要重新渲染等半天，现在改 frame(t) 刷新即看，灵感不断档。

会翻车的地方：别装错仓库，也别指望它替你想创意

两处容易翻车：第一，GitHub 同名仓库 WickyGinger/openfilm 是早期同名项目，star 和更新都停在过去，装错了技能装不上；第二，OpenFilm 是执行力拉满的「手」，但「脑」还是你——镜头语言、节奏、文案得你自己想清楚，Agent 只负责把你说清楚的东西变成画面。

另外实话实说，它目前最适合的是动态图形、产品展示、转场包装这类「代码友好型」视频；真人实拍素材的精剪、调色、混音，依然是传统剪辑软件的地盘。把它当成 Agent 时代的 After Effects 平替来用，心态就对了。
