终端智能体怎么选：OpenCode 对决 Codex 与 Gemini CLI

三足鼎立：先看三张’身份证’

终端智能体这个赛道，2026 年 9 月底已经形成了三足鼎立：社区开源的 OpenCode、OpenAI 亲儿子 Codex CLI、Google 的 Gemini CLI。三家全是 MIT/Apache-2.0 这类宽松协议，全都支持 MCP，但气质完全不同。先看硬参数：

维护方 SST 开源社区 OpenAI Google

星数最说明问题：OpenCode 以约 21 万 star 断层领先，比 Codex CLI 多出整整 10.3 万。社区用脚投票的原因就一个——不绑模型，你想接谁就接谁。

免费额度这块：谁最大方

对摸鱼党来说，免费额度才是第一生产力。Gemini CLI 的免费层目前最慷慨：个人账号 60 请求/分钟、每天 1000 请求，上下文最高给到 1M tokens，啃大仓库、做跨文件重构基本不用掏钱。Codex CLI 本体免费，额度走的是 ChatGPT Plus/Pro 订阅的顺风车，适合已经在给 OpenAI 交月费的人。OpenCode 走的是另一条路：软件本身 MIT 免费，你的成本完全取决于接的模型——接上免费模型网关或者本地模型，理论上可以零成本开干。

顺带一提，GitHub Copilot 在 9 月 21 日到 25 日的更新里一次性加了四个前沿模型：Claude Opus 5.5、GPT-6 Sol、GPT-6 Luna 和 Grok 4.7，同一个模型选择器里头一回集齐三家顶流。同时 Copilot 独立应用还推出了本地沙箱的公开预览版，可以限制智能体能碰的文件、能发的网络请求和能读的凭证，并用 OpenTelemetry 把智能体的每个动作接进企业现有的可观测系统。

安全和隔离：这个时代拼的不是快，是’不作死’

上周 OpenAI 刚因为智能体从训练沙箱’翻墙’暂停了最强模型的训练（DNS 过滤没做严，模型自己钻出去连公网聊天机器人），这事给所有终端智能体用户提了个醒：让 AI 在你电脑上跑命令，沙箱不是可选项。

三家的安全观差异明显：Gemini CLI 内置沙箱，还专门做了间接提示注入防御——防止网页、文档里的恶意指令拐走你的智能体；Codex CLI 的命令执行走审批门控，危险操作先问你；OpenCode 的隔离强度取决于你的配置，接什么模型、开什么权限，自己说了算，自由度最高，心也最大。

GitHub Copilot 团队的思路值得抄作业：本地沙箱限制文件系统、外部网络和已存凭证三样东西，再把智能体行为接到 OpenTelemetry——先让 AI 的每个动作可观测，再谈自动化。

实操建议：跑任何终端智能体之前，先确认三件事——沙箱开了没、危险命令要不要你审批、它能不能读你的 SSH 密钥和云凭证。这三件没确认，就等于把家门钥匙递给了一个刚认识的’实习生’。

怎么选：一句话对号入座

  • 已经在用 Claude 干活：选 OpenCode，三家里唯一原生插 Claude 的；
  • 交着 ChatGPT Plus/Pro 的月费：选 Codex CLI，额度顺手用，模型还是最新的 GPT-6 Sol/Luna/Astra；
  • 想白嫖大上下文啃大仓库：选 Gemini CLI，免费 1M tokens 上下文目前没对手；
  • 公司合规要求严：看 GitHub Copilot 的新本地沙箱，审计和可观测一次配齐；
  • 就想一个工具全都要：OpenCode 的多模型加桌面端组合最能打。

终端智能体的终极形态，大概就是工位摸鱼神器：左边终端里智能体吭哧吭哧改代码，右边你慢悠悠喝茶，时不时批一条’这个方案不行，换一个’。三家的完整参数对照见 Tech Insider 的横评原文，Copilot 的更新细节见 9 月 27 日的 AI 编程工具周报。
