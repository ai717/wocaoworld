GIF工厂做微信表情包：2119星Skill先小样再整套

 

给一张参考图：Codex按风格出整套GIF

做微信表情包最磨人的是整套风格统一：一张图好看，十六张放一起就散了。GIF 工厂是给 Codex 用的开源 Skill，2119 星、MIT 许可，装好后给一张参考图并说明风格，它按风格入口生成 GIF，像素、插画、真人、宠物、粘土吉祥物都能做，既能轻微点头摇摆，也能让角色完整做完挥手、行礼等动作。原先的 pixel-gif-sticker-pack 仓库已重定向到这里，调用名仍是 $pixel-gif-sticker-pack。

装法就一句话：把「帮我安装 GIF 工厂：https://github.com/WoYun520/gif-factory」发给 Codex。仓库里除了表情包，还有光栅变画卡、动态海报、动态签名、电影片头、文章封面配色、动态绘本和品牌短片几个 Skill，一般装总入口直接说需求就行，只用某个功能也可以单独装对应文件夹。运行时工具按功能分别准备，仓库的使用说明里有清单。

先做一张小样：认可了再扩成整套

仓库给的示例话术很实在：「用这张角色图做 12 张中文表情包，每张表情和姿势不同，加轻微点头或摇摆，文字用我给的这组台词。」更稳的打法是先做一张小样：指定画风、动作、文字、数量与尺寸，比如先做一张「收到」，角色点头、文字固定、透明边缘留安全距离，等你认可小样后整套沿用相同角色和配色。像素轻动效参考 320×320、循环约两秒，可作起点；整套里每张分别设计表情和姿势，反应才有区别。

另一条投递正好是实践帖：作者把两篇参考教程丢给 Codex 学习，自己只定角色和文案，自称已做出 16 张动态表情包并提交审核，长文里有可复制提示词，并链到 AYi、Punk 的原教程。「已提交审核」为作者自称，未核实；AYi 是 MoneyLab 已入选表情包定制案的作者，这条是其方法生态的实践帖，没有新变现证据。两条放一起看：GIF 工厂给工具链，实践帖给「教程喂给 Codex、自己只定角色文案」的分工。

导出前查四件事：透明裁切循环帧

脚本流程需要 Python 3 和 Pillow 导出 GIF，可选的 MP4 预览还需要支持 libx264 的 FFmpeg。导出脚本会检查数量、重复图片、动画是否变化、背景是否透明、是否裁掉内容以及压缩包能否打开。像素路线保留方格边缘，高清路线处理分辨率更高的姿态素材；连续帧里保持人物比例、落脚点和镜头一致，裁切突然变化就会显得跳动。提示词里要为头发、手与文字留空间，台词以中文为主时还要指向支持中文的字体文件。

微信投稿走官方开放平台，规格以平台当日要求为准。仓库的许可要分清：原创制作脚本与 Skill 说明是 MIT，但动态海报的角色与参考设计语言、光栅卡里的角色 IP、网络照片与他人插画不随代码转授商业权利，第三方配乐和字体按各自许可。用自己角色的图做表情没问题，拿别人 IP 出图商用要先过授权这一关。

适合谁用：已有吉祥物想批量出图的人

这套东西面向已经有卡通人物或吉祥物、想批量做一套聊天表情的人，省去自己搭动画流程。没有参考图时先花时间把角色定下来，参考图越清晰、轮廓越稳，整套一致性越好。生图走你环境里的图片服务，额度和费用另外算，Skill 本身不含生图额度。

 风格入口是做法组合，不保证每种素材与动作搭配都验证过，先一张小样再扩整套。实践帖里「16 张已提交审核」是作者自称未核实，投稿结果以微信表情开放平台审核为准。商用前分清 MIT 只覆盖脚本与说明，角色 IP 和字体配乐各有许可。

一句话收尾：GIF 工厂把「参考图加风格说明」变成可校验的出图流水线，适合先小样、再整套、最后查透明与裁切的节奏，别一上来就批量十六张赌运气。
