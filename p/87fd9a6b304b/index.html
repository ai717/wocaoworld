小红书运营技能2635星：托管分析选题全流程

 

分析选题能托管：小红书运营Skill全貌

运营小红书最耗时间的是三件事：看推荐流为什么推这些、分析自己账号哪篇为什么火、想下一条选题。xiaohongshu-ops-skill 是给 OpenClaw 等 Agent 用的小红书运营 Skill，2635 星、285 个 Fork，基于浏览器自动化 CDP，第一次需要扫码登录，后续无需重复验证。核心能力七项：首页推荐流分析、账号分析、选题灵感、知识库沉淀、自动发布、自动回复评论、爆款笔记复刻，另有目标笔记下载与 persona 人设文件。

仓库给了真实测试的精简结果：推荐流分析发现高互动内容集中在 AI 工具加踩坑复盘，高赞标题普遍是情绪词加具体对象；账号分析样本里置顶 AI 内容点赞 3191 与 1911，历史大量内容仅 1 到 10，结论是高赞来自 AI 热词加情绪冲突标题加置顶曝光；选题灵感产出 5 条可发选题并配互动钩子与三段结构。分析结果和动作保存为 markdown 知识库，仓库样本写有 2026 年 3 月记录，属常青项目，本周再次被推荐，同批介绍在 X。.

安装两条路：扫码登录后浏览器自动化

安装方法一是让 openclaw 或 codex 执行「帮我安装这个 skill，https://github.com/Xiangyu-CAS/xiaohongshu-ops-skill」；方法二是 clawhub install xiaohongshu-ops。仓库结构分工清楚：SKILL.md 是主逻辑与执行规则，persona.md 管人设语气，references/ 下有评论互动、发布流程、推荐流分析、账号体检、选题与知识库六份 SOP，knowledge-base/ 存分析结果与动作记录，默认本地保存并被 gitignore 忽略。

封面生成可能要 Gemini 密钥，仓库 2 月 27 日更新写了用 nano banana 生成封面并走图文发布流程，需要 gemini_api_key。自动发布能生成封面并上传、填写正文标题；自动回复评论逐个回复通知评论；爆款复刻输入笔记链接，分析爆款因素生成类似笔记含图文。

自动发布要谨慎：平台规则与版权风险

分析与选题是低风险区，自动发布、自动回评和按链接复刻是高风险区。自动发布与回评涉及平台对自动化行为的规则，账号安全与限流风险要自己承担；复刻笔记涉及原文案、图片的版权边界，生成相似笔记前先确认素材权利。建议用法是分级托管：分析、选题、知识库交给 Agent 全自动；发布与回评先人工确认再执行；复刻只借结构与钩子，文案图片全部重做。

仓库未声明开源协议，这一点商用或二次分发前要留意：没有协议不等于随便用，默认权利归作者。persona 人设文件决定对外文本语气，装好后先把人设与禁忌写清，再让它产出选题，免得风格漂移。

先跑分析再谈托管：三步验证顺序

验证顺序建议三步：先让它分析你的首页推荐流，看结论是否对得上你的实际感受；再让它分析你的账号，核对高赞低赞的归因；两步都靠谱再开选题灵感。自动发布最后开，且先小批量人工复核。知识库沉淀是这套 Skill 的复利项：每次分析落盘成 markdown，下次选题直接引用历史结论，越用越准。

 扫码登录后浏览器自动化长期在线，账号安全自己把关，发布回评建议人工确认。复刻笔记借结构不借原文案图片，版权风险先于流量。仓库未声明开源协议，商用分发前先联系作者确认。

适合谁：有小红书账号、想把分析选题系统化的人。先用分析与选题两项，托管发布等你验证完账号安全与平台规则再说。
