Harness²：不改权重让 Agent 越用越强

Harness² 是什么

Google Research 放出的开源框架 Harness²，全名 Recursive Agent Harnessing for an Open World，协议 Apache 2.0。它想解决的问题很实际：想让一个 AI Agent 变强，通常得回头去动模型本身，重新训练或者微调，门槛和成本都摆在那里。Harness² 的核心思路反过来：不碰模型权重，只改模型外面那层「脚手架」，靠「双层递归」让 Agent 在跑任务的过程中自我进化。默认执行器用 OpenCode，也可接 Codex；能改的组件一共有八类：系统提示词、护栏、记忆、工具指导、子智能体、Skills、脚本、插件。

第一层递归：任务级的 Propose–Probe–Compose

先把大任务拆成子问题（Propose），再逐个验证（Probe），最后把结果拼回去（Compose）。好处藏在中间那步：验证是逐个子问题做的，错在哪一环当场就能发现，而不是等整个任务跑完才发现结果不对、再从头返工。整个过程不需要人工提前写死流程，Agent 自己在运行时完成「提案-探测-合成」的循环。说白了，它把「一次交卷」变成了「边做边检查」，任务越复杂、环节越多，这种拆法的优势越明显。

第二层递归：经验沉淀成可复用组件

如果说第一层递归管的是「这一次任务怎么做」，第二层管的是「下一次任务能不能站在上一次的肩膀上」。跑完一轮后，Harness² 把成功的子流程、工具调用、记忆片段打包成 Skill 或插件存下来，下次遇到同类任务直接调用，不用再从零试错。这正是「越用越强」的来源：变强的不是模型本身，而是它周围越攒越厚的经验库。八大组件里，记忆、Skills、脚本、插件都是为这层沉淀留的口子；系统提示词、护栏、工具指导和子智能体的配置，则决定了它每一轮跑起来的行为方式。

实测提升：数字要看清口径

论文 给的三组数字是：WorkBuddy-Bench 最高 +11.5 分，JobBench 最高 +4.5 分，LAB 部分通过率最高 +11.8 个百分点。注意三组都是「最高」口径，不是平均提升，不同任务上的收益差别不小，JobBench 的 +4.5 就明显比 WorkBuddy-Bench 保守。把它理解成「上限演示」更稳妥：脚手架调对了，收益能摸到两位数；调不对，收益可能就没那么显眼。

本地一键体验与冷静提醒

想上手很简单：克隆仓库后直接运行 harness2-demo，无需任何模型凭据即可跑通演示，先看它怎么拆任务、怎么沉淀经验，再决定要不要往自己的流程里接。也要提醒一句：demo 免凭据跑通不等于真实任务零成本，真正干活时还得靠 OpenCode 或 Codex 这类执行器来驱动；另外，「不改权重」也意味着模型本身的能力上限还在那儿，脚手架能把现有能力用得更充分，却变不出模型本来没有的本事。
