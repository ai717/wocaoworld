Google Data Agent Kit 已 GA：直连 BigQuery

Google 在 2026 年 9 月 30 日正式把 Data Agent Kit 推向 GA，插件仓库版本分别为 1.0.0（9 月 29 日）与 1.1.0（10 月 13 日）。此次 GA 新增 BigQuery Graph、Bigtable、Managed Service for Apache Spark，合计可连接 15 个以上 Google Data Cloud 服务。同时官方宣布兼容 Antigravity、Claude Code、Codex 以及 Cursor、VS Code 等编辑器扩展，Cloud Shell 与 Cloud Workstations 已预装。

这意味着开发者不再需要手写复杂的 MCP 适配层，直接在熟悉的 IDE 里让 Claude Code 或 Codex 发起 SQL 查询，甚至把结果喂回模型继续推理。对数据团队而言，BigQuery、Bigtable 等核心仓库瞬间变成“可对话”的资源，极大降低了从原型到生产的门槛。

  • 双层护栏：37 个 Apache 2.0 skills 只做建议，accidental-data-loss-prevention 会在 DROP TABLE、TRUNCATE、无 WHERE 的 DELETE 前强制确认；真正的硬锁在 IAM 拒绝策略，按 tool.isReadOnly 为 false 直接拦截非只读调用。
  • 权限透传：每一步都走用户自己的 IAM 权限，管理员可用服务账号模拟实现行列级安全，再配合 Model Armor 与 VPC Service Controls 做网络层隔离。
  • 即插即用：Cloud Shell 与 Cloud Workstations 预装，无需本地配置即可在浏览器里跑通完整链路。

虽然 GA 带来了完整的技能集与 IAM 级硬锁，但在实际落地时仍需注意几点：先看，官方强烈建议“先只读、连一个数据集、问一个 recurring 问题”，不要一上来就把写库权限交给 agent，否则一条误触发的 DELETE 就可能触发拒绝策略导致任务中断。再看，Model Armor 与 VPC Service Controls 属于企业级组件，小团队可能暂时用不到，导致安全审计链路不完整。再次，技能列表虽有 37 条，但目前仅覆盖常见查询与元数据操作，复杂的多表事务、存储过程调用仍需自行扩展。最后，兼容性声明里列出的 Antigravity、Cursor 等 IDE 扩展处于快速迭代期，版本不一致可能引发 MCP 协议握手失败，建议在生产前先在 Cloud Shell 做完整冒烟测试。
