Browser Use 让 AI 自己开浏览器：89.1% 准确率

 

为什么要让 AI 自己开浏览器

以前要让大模型完成网页任务，得人工截图、喂 DOM、再一步步指挥点击，效率低还容易卡在动态渲染里。Browser Use 把浏览器当成一双「手」直接交给模型，它能自主加载页面、定位元素、翻页下载，连复杂的表单也能一次跑通。官方首页的演示就是让它自己找空位、挑时间、过验证码、订一场驾考。官方在 WebVoyager 基准上跑出 89.1% 准确率，Stealth Bench V2 上也有 90.5%，意味着真实网站里十个任务有九个能全自动完成。项目拿了 1700 万美元种子轮融资，GitHub 约 12 万星，版本迭代很快。

本地跑通的最小准备

Python 3.11+ 环境，uv add browser-use（或 pip install browser-use）就能拿到核心库。再按官方示例写个 agent.py：from browser_use import Agent, ChatOpenAI，Agent(task='查一下 browser-use 仓库有多少星', llm=llm)，uv run agent.py 跑起来，浏览器自己打开、自己查、自己把答案打出来。Claude、GPT、Gemini 都能接，官方还推了自家为浏览器自动化优化的 BU2 模型（ChatBrowserUse，model=’bu-2-0’），本地模型走 Ollama 也行，库本身免费、MIT 协议。

三条路：云端、CLI、Python 库，照官方分法选

官方把用法分成三条路，按你要管多少东西选。第一条，全托管云端：任务直接发给官方 API，Agent、浏览器、基础设施全由官方跑，新用户用 Google、GitHub 或微软账号注册送 1 美元云端额度。第二条，CLI：browser-use skill install 把技能注册进 Claude Code、Codex、Hermes、OpenClaw、Cursor 这类你已有的 Agent，之后直接用自然语言指挥它操作你自己的浏览器，交互式用、写进脚本里用都行。第三条，Python 库：就是上一节的 agent.py 写法，自己写代码、接模型、定输出，本地浏览器或云端浏览器都能接。

云端版 Browser Use Cloud 省事但要算账

云端版把浏览器实例托管在官方集群，按实际运行时长计费，官方标价每小时 0.02 美元（另加少量流量费），折合人民币约 0.14 元，还自带 stealth 反检测、住宅代理、验证码处理和实时查看链接。适合偶尔跑长任务、不想折腾驱动和显存的场景，新注册送的 1 美元额度够先试几把。但高频、大并发时费用会线性上涨，建议先在本地跑小规模验证，再决定是否迁移上云。

常见翻车点别踩

1️⃣ 网页若大量使用 Canvas/WebGL 渲染，元素定位可能失效，需改用坐标点击或等待官方支持。 2️⃣ 验证码这关官方也不打包票：云端浏览器自带 stealth 与住宅代理，能降低被拦的概率，但不保证每次都能过，关键任务留好人工介入的口子。 3️⃣ 模型上下文窗口不够长时，长页面会被截断导致任务中断，需自行做分段摘要或增大上下文。 4️⃣ 版本更新快（v0.13.13 2026‑10‑15 发布），依赖库若不锁定版本容易出现破坏性变更，生产环境请锁定 browser-use==0.13.13。

12 万星之后：先从一个小任务试起

完整 API、插件系统、自定义动作空间都在 GitHub 仓库 的 README 与文档站里。社区里已经有人拿它做自动化测试、数据采集、电商比价，克隆下来改改 Prompt 就能上手。MIT 协议允许商业闭源嵌入，放心拿去二次开发。建议先拿「查一下某个仓库多少星」这种小任务跑通全流程，再去碰订票、填表这类真金白银的操作。
