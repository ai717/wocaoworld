Skill 装多了不会用？v2.1.0 让 Claude Code 学会技能路由

 

Skill 装了 30 个，Claude Code 还是每回都问“这活谁来干”

玩 Claude Code 的人迟早会掉进同一个坑：Skill 越装越多，agent 反而越不会干活。写 API 的时候它去翻部署文档，修 bug 的时候它先给你出一份“重构计划”。你只好在每个任务开头复读一遍：“这个阶段听 api-designer 的，别的不许插嘴。”说三遍之后，你开始怀疑到底是谁在给谁打工。

台湾独立开发者 eric861129 写的 Workflow Skill Router 就是来治这个毛病的。它的思路很直白：开工之前，先按阶段挑一个主导 Skill，只给这个阶段配真正需要的辅助 Skill，还把路由摊开给你看。11 月 1 日发布的 v2.1.0 最大的变化，是这套东西终于原生支持 Claude Code 了——以前它只给 Codex 用。

动手前先看一眼：你的机器够不够格

装之前确认两样东西。第一，终端 PATH 里有 Node.js 24 以上版本；第二，有 Python 3.11 以上。插件自带编译好的 MCP bundle 和 Python Runtime，安装时不会跑 npm，也不会顺手给你装别的 Skill，这点很干净。

另外想清楚你是不是目标用户：如果你同时在用 Claude Code 和 Codex，或者 Skill 已经装了一大堆、每次开工都要重新交代谁主导，这插件就是为你写的。如果你只用 Claude Code 且 Skill 就三四个，那它帮你省的那句话还不够回本，可以直接划走。

两行命令，把同一套 Skill Tree 交给 Claude Code

在 Claude Code 里敲这两行：

/plugin marketplace add eric861129/Workflow-skill-router

/plugin install workflow-skill-router@workflow-skill-router

装完之后，Claude Code 会优先读工作区里的 .claude/workflow-skill-router.json 这份个人路由配置，找不到才回退到 .codex/workflow-skill-router.json。你的个人 Skill Tree、本地状态，Codex 那边装了同一个插件的话是完全共用的——在一边调好的工作流，换到另一边直接生效，不用再讲一遍规则。

装完先验货：新开一个 Claude Code 会话，直接问它“Show the Workflow Skill Router status and explain which capabilities are available in this environment.”如果它报出 bundled-local-r0 这个运行时，说明本地 MCP Server 正常启动，路由能力就绪。

它到底替你省了哪句话：每阶段只点一个主将

Router 的核心动作就一个：分阶段点将。比如你要“交付 API 的契约、实现和测试”，它会拆成三段——契约阶段主将是 api-designer，配一个 api-guidelines-skill 打辅助，出口条件是 contract-reviewed；实现阶段换将，验证阶段再换。任何时候都只有当前阶段的 Skill 生效，进下一阶段重新路由。

还有两处细节很对味。第一是“点名锁定”：你在任务里点名要某个 Skill，它就当主将，Router 想加辅助必须先说明目的、范围、拒绝的后果和上下文成本，你点头才算数。第二是“先验后信”：计划里的每个 Skill 都会先标成 intended-unverified，等运行时确认环境里真的装了、真的可用，才转正——计划里写了不等于真有，这话实在。

v2.1.0 还带了个默认关闭的 Workflow Memory：新增 8 个 MCP 工具，能记录完成的路由、提出可审查的 Profile 更新，还能回滚和清除。想让它越用越懂你，就把这个开关打开。

先别急着吹：作者自己都没敢打包票的三件事

这个项目最难得的是诚实。README 里专门有一节讲证据和边界，翻译成人话就是三盆冷水。第一，完整指令包会让输入 token 增加约 26% 到 28%，省没省钱、快没快、代码变没变好，一律没测出来，别自己脑补。第二，路由评测测的是“选 Skill 选得对不对”，不是“软件做得好不好”，36 次评测跑的是 claude-sonnet-5-5，结论别外推到别的模型。第三，插件的完整功能只在能加载本地 MCP Server 的地方有——终端、IDE、桌面版 Claude 的 Code 分页；在 claude.ai 网页版里只有 Skill 会加载，以无状态的降级模式运行。

还有个版本小坑：给 Codex 用的最新发布其实是 v2.1.2，修了 plan_work 的一个解析问题；v2.1.0 是 Claude Code 支持的首个版本。两边都用的人，记得各装各的新版。

什么人现在就该装

排第一的是双持党：Codex 里调好的 Personal Routing Profile，Claude Code 这边直接读到，这是 v2.1.0 最实在的价值。排第二的是 Skill 囤积党：每次开工都要交代“这个阶段谁主导”的，配一份个人路由配置一劳永逸。至于只用 Claude Code、Skill 屈指可数的人——等你的 Skill 多到自己都记不清再回来，完全来得及。

项目本身很小，GitHub 上只有十几个 star，MIT 开源，作者还准备了繁体中文文档。这种体量的个人项目能自己做 36 次模型评测、把“没证明的东西”写进 README，比很多大厂通告都值得信一次。原文参考：v2.1.0 Release、ChiYu Code Journey 完整评测。
