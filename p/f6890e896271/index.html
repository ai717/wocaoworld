DeepAI 免费模型全解析：27 个模型 250 额度怎么花

 

官网列出的 27 个模型：13 个实验室全到齐

写代码这件事，选模型比拼手速重要得多。DeepAI Code 的官网页面把自家编程助手里能用的模型一次摊开：27 个模型、13 个实验室，Claude Sonnet 5.5、Claude Opus 5.5、GPT-6.1 Terra、GPT-6.1 Sol、Gemini 4 Argon、Gemini 4 Hydrogen、Gemini 4 Carbon、Muse Spark 1.3、Claude Fable 5.2 全在名单里。消息来自 X 上的一条爆料帖，下面逐项拿官网原文来验。注意措辞：这些型号是 DeepAI Code 内置的接入名，不是 Anthropic / OpenAI / Google 官方发布的型号，读的时候先把这个定语记牢。

名单里还有 MiniMax M3、GLM 5.3、Kimi K3 与 Kimi K3.1 Pro、Qwen 3.8 Max Prime、Muse Wonder、GPT-6 Astra，以及 DeepSeek V4.1 Flash、MiMo 2.6 系列、GPT-6 Luna 这类轻量型号。Mac、Windows 与 Linux 三端都有客户端，下载安装后登录免费账号就能开用，不用信用卡，也不用自己准备 API Key。

免费额度账本：11 个不限量加每天 250 个 Theos

免费口径是官网原话，不用猜：11 个 unmetered 模型不花 Theos，其余 16 个前沿模型共享每日免费 Theos 额度，免费账号每天最多 250 个 Theos，$0、无需信用卡、无需 API Key。官网还写明，DeepAI Code 靠广告支撑，11 个不限量模型在任何账号上都不花 Theos。

不限量那 11 个包括 GLM 5.3 Flash、DeepSeek V4.1 Flash、MiMo 2.6 Flash、Qwen 3.8 Flash、MiniMax M3.1 Flash、Muse Ember、Solar Mini 4、GPT-6 Luna、MiMo 2.6 Pro、Glyph Cluster 与 DeepAI Cyber。日常改 bug、写小脚本、补注释这类活，交给不限量模型基本不花钱，250 个 Theos 留给前沿模型。

额度每天刷新，用不完不累计。Pro 账号每天最多 450 个 Theos，比免费账号多 200 个。官网的说法是，免费账号的额度在上次发放 24 小时后刷新，写长任务前先看一眼余额，免得跑到一半断粮。

免费真能用上 Sonnet 5.5 本尊吗：存疑点先说清

羊毛最值得较真的一点，是免费档背后到底跑的是哪个模型。独立测试 freebuff.com 在 2026 年 11 月 10 日的文章里发现，11 月 7 日到 8 日，免费档的回答实际走的是 OpenRouter 匿名 stealth 模型 Crouton Alpha 的端点；11 月 10 日应用强制更新后，stealth 标记消失，前沿模型才显示各厂商自己的格式，DeepAI 对此没有作过解释。也就是说，免费真能用上 Sonnet 5.5 本尊这件事有过争议，11 月 10 日之后改没改彻底，目前没定论。

这个存疑点不影响不限量模型的使用，但影响你怎么看前沿模型那栏。稳妥的做法是：把 DeepAI Code 当成一个免费的模型聚合入口来试，关键任务先用小问题验一下回答风格与能力，再决定要不要把重要代码交过去；真要长期依赖某个厂商的旗舰模型，还是走厂商自己的官方渠道更踏实。

另外注意一点：DeepAI Code 也支持接入 ChatGPT、Claude、Cursor、Grok、OpenCode 与 Antigravity 这些外部账号，接进来之后用量算在你自己的订阅里，不扣 Theos；它还能直接打开你已有的 Claude Code 与 Codex 项目。免费入口与付费订阅可以并存，不用二选一。

每天 250 额度花在刀刃上：三类任务分流建议

额度有限，先分流再动手。第一类是日常杂活：改报错、补测试、写注释、整理代码结构，交给 11 个不限量模型，零成本先跑一遍，大多数小任务到这一步就结束了。第二类是中等难度：重构一个模块、写一个新功能、给老项目加接口，用 GPT-6.1 Terra 这类每次约 5 个 Theos 的模型，250 额度一天能跑几十次。

第三类才是重型任务：跨文件的大重构、看不懂的祖传代码、需要强推理的算法实现，再点 Sonnet 5.5 或 Opus 5.5 这类每次 10 到 15 个 Theos 的模型。GPT-6 Astra 每次约 50 个 Theos，一天 250 额度只够五次，留给卡了半天也没思路的硬骨头。

还有一个省额度的习惯：让模型先读代码再动手，描述任务时把报错原文与期望结果一次贴全，减少来回追问的轮次。任务拆得越细，单次请求花得越少，免费额度撑得越久。
