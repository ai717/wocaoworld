四步把网站推上线：从注册到绑定自己的域名

官网给出的流程是四步，前三步几分钟就能走完。第一步免费注册，邮箱、Google、GitHub、GitLab 或 Bitbucket 都可以，不用信用卡。第二步把网站交过去：上传文件夹或 zip、连接 Git 仓库，或者让 Claude、ChatGPT、Cursor、Codex 通过 MCP 发布。

第三步挑地址，网站上线到 yourname.cloudzyro.app，带 HTTPS，大多数站点约一分钟就能访问。第四步在站点的 Domains 标签页加上自己的域名，证书由平台配置好。部署方式上，平台会读你的项目、构建并保持运行，新版本只有启动成功并能响应之后才会上线。

团队成员不收费，邀请多少人都不加钱。每个站点跑在自己的容器里，有独立的内存与 CPU，互相碰不到。被 Cloudflare 拦截的攻击流量不计入 100GB 额度，这一点对小站很友好。

静态看板能搭，探针监控不能装：这条红线先划清

免费档配一个私人看板，思路要先摆正：静态页面可以搭，探针监控不能装。Cloudzyro 官网在免费页的禁令清单里写得非常直接：服务器探针与 VPS 监控属于零容忍禁装，包括 Nezha、Komari、ServerStatus 这类探针面板与它们的 Agent，以及 X-UI 这类节点面板；一旦触犯，账号连同名下全部站点一起移除，而且禁止再次注册，连上传被拒绝都算数。

这意味着“用免费档搭一个 VPS 状态监控中心”这条路是走不通的，装探针 Agent 去采集 VPS 的 CPU 与内存数据，踩的就是这条红线。看板本身没问题，问题在数据怎么来：凡是需要在 VPS 上装 Agent、定时上报状态的方案，都不要往 Cloudzyro 的免费档上放。

能做的看板是静态的那种：一个纯静态页面，上面放你的 VPS 厂商控制台链接、每台机器的套餐与到期日、免费额度与羊毛的剩余情况，数据由你手动更新，页面本身不主动探测任何服务器。静态站不休眠，打开就是现成的，刚好适合放这种个人小工具。

三步搭一个静态额度看板：Muse 生成页面加手动更新

静态看板的做法很简单。第一步，让 Muse 按你的清单生成一个单页 HTML：顶部是各台 VPS 的套餐、到期日与月流量，中间是手里在薅的免费额度与到期提醒，底部放常用控制台的链接。第二步，把生成的页面当作静态站推到 Cloudzyro：上传文件夹或连 Git 仓库，拿到 cloudzyro.app 的地址，再绑自己的域名。

第三步是日常维护：额度与到期日变了就改一下页面里的数据文件，再重新部署一次。部署命令用你自己的仓库流程即可，例如 git push origin main 推上去触发构建；想确认页面是不是通的，跑一句 curl -I https://yourname.cloudzyro.app 看返回码是不是 200。

页面里别放任何实时探测逻辑，也别在 VPS 上装任何上报程序。额度数字可以手写进一个简单的 quotas.json 文件，页面读它渲染，改数字、重新部署、刷新页面就能看到新数据。免费档的静态站不休眠，这个看板随开随看，不用担心冷启动。

免费档的四条边界：没永久磁盘与 WordPress 不在内

第一条边界是磁盘：免费档没有永久磁盘，应用运行中写入的文件每次重新部署都会清空。账号、订单与上传内容要放在数据库里，官网建议用 Supabase 或 Neon 这类外部数据库，密钥放进锁定的环境变量，别写进代码。

第二条边界是类型：免费档跑静态站、单页应用与 Node.js 应用，WordPress 与 PHP 站点需要走另外的 Web Hosting 套餐，不在免费档里。第三条边界是域名数量：免费档每个站点只能绑 1 个自定义域名，example.com 与 www.example.com 算一个，多域名要升级到 Boost。

第四条边界是上传与版本：单次上传限 100MB，每个版本最多 2 万个文件，只能恢复最近 5 个版本。流量超了只限速不断网，攻击流量被拦截的不计费，团队成员免费。免费页最后更新于 2026 年 11 月 14 日，动手前以官网当前页面为准。
