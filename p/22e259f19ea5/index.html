AI 写的界面总一个味？impeccable 用 62 条规则专治紫色渐变

AI 界面为啥总长一个样

让 AI 写个落地页，十有八九是紫色渐变背景、卡片里再套卡片、全局 Inter 字体，再配个圆角小图标。Paul Bakaus（jQuery UI 作者、前 Google 工程师）把这套「AI 味」审美总结成 62 条确定性规则，打包成impeccable这个开源技能：2025 年 11 月开源，不到一年攒下超 9.5 万 star，2026 年 10 月 26 日又冲上GitHub Trending 日榜，单日涨 1100+ 星——大家是真不想再手动改紫色渐变了。

一行命令装进你的 AI 编程工具

在项目根目录跑 npx impeccable install，安装器会自动识别你机器上的 AI 编程工具：Claude Code、Cursor、Codex、GitHub Copilot、Gemini CLI、Grok Build 都在支持列表里，自己选装到当前项目还是全局。装完在智能体里敲 /impeccable init，它会读你的代码、问几个实在答不上来才问的问题，然后写出一份 PRODUCT.md：产品定位、用户、约束、视觉基调一次定死，以后每条命令都照着这份文档干，不用每次重新猜你要啥风格。

audit 和 critique：先打分，再动手改

/impeccable audit 跑的是技术审查：无障碍、性能、响应式三大项，62 条规则全是确定性静态分析，不跑 LLM、不要 API Key，扫完直接告诉你哪行违了哪条、该怎么改。/impeccable critique 则是打分式 UX 评审，按视觉层级、交互一致性等维度给页面打分，分数低的地方附修改建议。一个管「对不对」，一个管「好不好看」，分工很清楚。

钩子：改完 UI 文件自动跑一遍

最省事的是安装时带的 design hook：在 Claude Code、Cursor、Codex、GitHub Copilot、Grok Build 上，智能体每次改完 UI 文件，钩子会自动跑一遍检测，把问题直接喂回给智能体，不用你记得去跑命令。想在 CI 里卡门禁也行：npx impeccable detect src/ 扫源码目录，加 --json 还能吐机器可读的结果接流水线。

polish：发版前的最后一遍

收尾用 /impeccable polish 做发布前精修，/impeccable harden 补错误态、国际化、溢出这些边缘情况。整套技能 Apache-2.0 开源，完整命令手册都在impeccable.style。说白了，它干的就是一件事：把「别再紫色渐变了」这种口头审美，变成机器能执行的检查项。
