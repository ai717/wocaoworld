Stitch设计Skill免费开放16个：先装再谈审美

 

16个Skill分三组：设计、搭建、工具各管什么

谷歌实验室把 Stitch 的 AI 画界面能力拆成了 16 个免费 Skill，装进 Claude Code、Cursor、Codex 或 Antigravity 这类编码 Agent 之后，AI 不只会写代码，还会管审美。官方仓库已经攒下约 1.27 万星，Apache 2.0 开源，16 个 Skill 按三组插件分：设计组 6 个、搭建组 5 个、工具组 5 个。

设计组管“画什么样”：生成新界面、改现有界面、从前端代码反推设计稿、上传设计系统、抽静态 HTML、传本地素材进 Stitch。搭建组管“怎么落地”：把 Stitch 界面转成 React 组件、React Native 组件、React 加 Vite 仪表盘，用 Remotion 做走场视频，接 shadcn/ui。工具组管“别跑偏”：生成 DESIGN.md 与 SITE.md、优化提示词、按审美标准卡设计质量、一句话生成多页网站。

一条命令装进Claude Code：先把MCP这道坎迈过去

安装本身不难。Claude Code 与 Cursor 用户一条命令就能装进当前项目或工作区：

npx plugins add google-labs-code/stitch-skills --scope project --target claude-code

npx skills add google-labs-code/stitch-skills

Codex 用户先把仓库加为插件市场再装三组插件，OpenCode 用户手动把 Skill 文件夹拷进 .opencode/skills。但真正的前置条件不在安装，而在 Stitch MCP：这些 Skill 要靠 Stitch MCP 服务器才能在 Agent 环境里跑通，没配好 MCP 就装 Skill，等于只装了说明书没接电源。先去 Stitch 官网走完 MCP 配置流程，再谈用 Skill 出图。

先定配色字体再出页面：这套流程值在哪

Stitch Skill 的核心思路是反着来的：不是先出页面再修审美，而是先定配色、字体与排版这些设计系统，再让 AI 在约束里出页面。manage-design-system 这个 Skill 就是干这个的：上传一份 DESIGN.md，全站风格就锁死了，之后生成的每个界面都照着同一套走，避免“一页一个样”的廉价感。

实操上建议的顺序是：用 generate-design 出第一版界面，extract-design-md 从现有前端代码里抽出设计系统，manage-design-system 把它固化下来，react-components 再把界面转成带设计 token 的 React 组件。个人项目与小团队做官网、落地页、管理后台，这条链路比从零手写 CSS 快得多，而且风格统一是 AI 出图最容易翻车的地方，这套 Skill 正好卡住了这个点。

 Skill 之间有依赖关系，挑着装容易缺件，官方建议整组装。OpenCode 下 Skill 名字要改成小写 kebab-case 才能被识别。最重要的一点：没配 Stitch MCP 之前别急着下结论说 Skill 不好用，先把 MCP 跑通。

总的来说，这 16 个 Skill 不是给设计师的玩具，是给写代码的人补审美短板的：免费、开源、装一次长期用，前提是先把 MCP 这道坎迈过去。
