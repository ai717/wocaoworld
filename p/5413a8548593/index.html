Mercury3 1068 token/s 百万上下文首发半价

核心参数一览

Inception 刚把 Mercury 3 推到台面，这是它家的新一代扩散大模型（diffusion LLM）。官方新闻稿 2026-10-19 发布，给的硬指标有两个：NVIDIA GPU 上实测 1,068 tokens/秒 的生成速度，上下文窗口 1,000,000 token。上一代 Mercury 2.5 的上下文只有 260,000 token，这一代直接拉高到接近四倍。unite.ai 的报道 也把速度和上下文这两项列为这代的主打卖点。

扩散架构为什么能这么快

市面上大多数大模型是自回归的：一个 token 接一个 token 往外吐，前一个没写完，后一个不能动，速度天然被串行卡住。扩散模型的路子不一样，更像图像扩散生成图片的过程：先给出一整段粗稿，再并行地多轮修整、逐步定稿。能并行，吞吐就上去了——1,068 tokens/秒意味着上千 token 的回答一秒内就能吐完，这个速度放在实时对话、代码补全这类等不起的场景里，体感差别非常明显。代价是生成方式和传统模型完全不同，写长文本时连贯性到底稳不稳，还得等更多人实测。

价格与接入

首发五折：输入 $0.10/百万 token、输出 $0.35/百万 token，缓存输入只要 $0.01/百万。注意这是首发价，标准价是输入 $0.20、输出 $0.70、缓存输入 $0.02，恢复原价后整体翻倍。缓存输入便宜，对重复喂同一份长文档的场景特别友好：百万上下文塞进去一次，后面反复提问，命中的部分按 $0.01 算。接入渠道有四个：Inception API、Baseten、OpenRouter、Vercel，其中 Vercel 走 OpenAI API 兼容，已经在用 OpenAI 格式的项目迁移起来比较省事。

行业冲击与突破点

  • 同级别模型里首个把百万上下文与千 token 级吞吐同时做到，速度和容量不再二选一
  • 扩散架构让并行解码成为常态，推理延迟大幅降低，实时交互场景的门槛被拉低
  • 半价首发直接把同档的 GPT-6 Luna、Claude Haiku 5.5 等参照对象逼入价格战，不过竞品参数官方未给，别轻信网传对比

真实局限

泼几盆冷水。速度数据来自 NVIDIA GPU 实测，其他硬件表现未公开，而且 1,068 tokens/秒是官方口径的成绩，日常调用能跑到多少，还要看接入渠道和并发情况；扩散模型在长文本连贯性上仍需更多实战验证；首发半价是限时打法，做长期预算时要按标准价算账，成本得翻倍预估。信息源头也说明一下：联合创始人 Stefano Ermon 在 X 上的发布动态，目前仅见 Interesting Engineering 报道 转述，未拿到原帖直链，所以本文只采用官方新闻稿与已公开报道里的数据。
